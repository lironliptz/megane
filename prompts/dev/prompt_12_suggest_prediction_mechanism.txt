## Problem (current behavior)

Megane has successfully assembled a rich, multi-modal database of corporate intelligence:
1. **SEC Filings & Timelines:** Dates, form types, and event weights (major, medium, minor).
2. **Extracted Financials:** Revenue, Net Income, EPS, Cash, and their historical trends.
3. **Analyst Consensus & Surprises:** Price targets, rating distributions, and earnings surprises.
4. **Market Data:** Daily adjusted close prices, trading volumes, and historical volatility.

However, these data streams currently sit in silos. Megane is purely **retrospective**: it displays what happened in the past but does not help users answer the ultimate investment questions:
* *Which events actually move the stock, and by how much?*
* *What is the statistical correlation between an earnings surprise of $+X\%$ and the subsequent 5-day return?*
* *Can we predict the short-term price direction (e.g., next 3 to 5 days) following a major corporate announcement?*

To solve this, we must build a **Prediction & Correlation Engine** that extracts predictive features from historical events, calculates statistical correlations, and trains a cross-company predictive model.

## Scope & non-goals

**In scope**
- **Multi-Day Prediction Windows:** Predicting cumulative returns or Cumulative Abnormal Returns (CAR) over $T_{+1} \to T_{+3}$ and $T_{+1} \to T_{+5}$ trading days.
- **Cross-Sectional Training:** Training models on historical data from *many* companies to learn generalizable event-driven patterns (e.g., how the market reacts to a Q2 revenue beat).
- **Multi-Modal Feature Extraction:** Combining categorical (form types), numerical (surprises, momentum), and textual (event summaries) features.
- **Explainable Predictions:** Displaying feature contributions (why the model made a prediction).

**Out of scope**
- **Intra-day / High-Frequency Trading:** No real-time tick data or sub-daily predictions.
- **Automated Order Execution:** The engine is purely advisory; it does not place trades.
- **Unstructured Social Media Scrapers:** No scraping of Reddit, Twitter, or message boards.

## Feature Engineering Design

For every historical event of interest at date $T_0$, the pipeline constructs a training/inference vector containing four categories of features, ensuring **no lookahead bias** (all features are calculated using data available at or before $T_0$, and the target variable begins at $T_{+1}$).

### 1. Filing & Event Features (Categorical & Ordinal)
* `form_type`: Form 10-K, 10-Q, 8-K, 20-F, 6-K, etc.
* `event_category`: Financial, Governance, Regulatory, Insider, Analyst, etc.
* `event_weight`: Numerical mapping of event severity (Minor = 1, Medium = 2, Major = 3).
* `days_since_last_event`: Time elapsed since the company's previous public announcement.

### 2. Financial Surprise Features (Numerical)
* `revenue_surprise_pct`: $\frac{\text{Actual Revenue} - \text{Consensus Estimate}}{\text{Consensus Estimate}} \times 100$ (from prompt 11).
* `eps_surprise_pct`: $\frac{\text{Actual EPS} - \text{Consensus Estimate}}{\text{Consensus Estimate}} \times 100$ (from prompt 11).
* `operating_margin_change`: Change in operating margin compared to the same quarter last year.
* `is_annual_report`: Boolean flag (annual reports typically carry higher market weight).

### 3. Analyst Sentiment Features (Numerical)
* `consensus_pt_change_30d`: Percentage change in the consensus price target over the preceding 30 days.
* `rating_upgrade_indicator`: $+1$ for upgrade, $-1$ for downgrade, $0$ for reiteration.
* `buy_ratio`: $\frac{\text{Buy Ratings}}{\text{Total Ratings}}$ in the active consensus.

### 4. Market Momentum Features (Numerical)
* `historical_volatility_30d`: Standard deviation of daily returns over the preceding 30 trading days.
* `price_momentum_30d`: Cumulative return of the stock over the preceding 30 trading days.
* `relative_strength_index_14d`: Standard 14-day RSI to identify overbought/oversold states.
* `volume_spike_ratio`: $\frac{\text{Volume}_{T_0}}{\text{Moving Average}(Volume)_{30d}}$ (identifies high-liquidity breakouts).

### 5. Target Variable: Cumulative Abnormal Return (CAR)
To isolate the event's true impact from broader market movements, the target variable is the **Cumulative Abnormal Return (CAR)** over a 5-day window:
$$\text{CAR}_{5\text{D}} = \sum_{t=1}^{5} \left( R_{\text{stock}, T+t} - R_{\text{market}, T+t} \right)$$
Where $R_{\text{market}}$ is the return of a benchmark index (e.g., S&P 500 or NASDAQ-100) on trading day $T+t$.

## Model Architecture

The prediction engine implements a **Dual-Engine Architecture** to combine quantitative rigor with qualitative reasoning:

```
                  ┌────────────────────────────────────────┐
                  │          Historical Event Data         │
                  └───────────────────┬────────────────────┘
                                      │
                         [ Feature Extraction Pipeline ]
                                      │
                  ┌───────────────────┴────────────────────┐
                  ▼                                        ▼
     ┌─────────────────────────┐              ┌─────────────────────────┐
     │   Quantitative Engine   │              │    Qualitative Engine   │
     │ (Go-Native Random Forest│              │ (Gemini Structured LLM) │
     │   or Ridge Regression)  │              │                         │
     └────────────┬────────────┘              └────────────┬────────────┘
                  │                                        │
                  └───────────────────┬────────────────────┘
                                      ▼
                  ┌────────────────────────────────────────┐
                  │           Ensemble Predictor           │
                  │  (Weighted Probability & Explanation)  │
                  └────────────────────────────────────────┘
```

1. **Quantitative Engine (Go-Native):**
   - Uses a Go-native machine learning library (e.g., `github.com/sjwhitworth/golearn` or a custom decision tree implementation) trained on cross-company historical data.
   - Outputs a raw expected return magnitude and a statistical confidence interval.
2. **Qualitative Engine (Gemini LLM):**
   - Invokes Gemini using a highly structured JSON schema.
   - Prompt passes the engineered feature vector, the historical correlation matrix, and the event's textual summary.
   - Outputs a structured prediction: direction (Bullish/Bearish/Neutral), probability, and a 2-sentence investment thesis.

## Pitfalls to Avoid

- **Lookahead Bias & Data Leakage:** Never include any information from $T_{+1}$ or later in the feature vector. The target return must start strictly on $T_{+1}$ (excluding $T_0$ to prevent in-day execution leakage).
- **Overfitting on a Single Ticker:** Do not train a separate model per company. The model must be trained cross-sectionally across the entire multi-company database to capture robust, generalizable market principles.
- **Ignoring Market Regimes:** A positive earnings surprise in a bear market may result in a flat or negative price reaction. Always include the benchmark index return ($R_{\text{market}}$) or a market-wide volatility feature (e.g., VIX or index momentum) to control for market regimes.
- **Illiquid Stocks:** Small-cap or illiquid stocks can have highly volatile, erratic price reactions. Exclude events from companies with average daily trading volumes below a minimum threshold (e.g., $50\text{K}$ shares) during training.
