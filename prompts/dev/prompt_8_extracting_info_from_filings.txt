=== prompt ===
**Deep financial extraction** from on-disk SEC filings — after prompt 2's `meta.json`
(classification, headline summary, tags).

Goal: deterministic parsing of **rendered financial HTML** (`R*.htm`) into structured
numbers that feed the Timeline event modal and chart callouts (prompt 6). Prefer **no LLM**
for the happy path; add an optional LLM fallback only when parsing confidence is low.

**Stack:** Go in `internal/edgar/` (ingest) + `internal/companyview/` (read path for API).
**Storage:** JSON beside each accession in `fileDB/` (same phase-1 pattern as `meta.json`).

**`R*.htm` plain HTML tables** — human-readable labels, no XBRL taxonomy parser required.

## Why `R*.htm` (measured takeaway)

For Kamada quarterly 6-K filings, the pragmatic extraction target is **`R*.htm`**:

| File | Typical content |
|------|-----------------|
| `R2.htm` | Balance sheet — cash, total assets, liabilities |
| `R3.htm` | Income statement — revenue, gross profit, operating income, net income, EPS |
| `R5.htm` | Cash flows — operating cash flow, net income reconciliation |
| `R20.htm` | Segment breakdown — revenue by line of business |
| `R1.htm`, `R4.htm`, … | Entity info, comprehensive income, equity — lower priority |

Example numbers available in one filing (Q3'25 style columns):

- **R3:** Total revenues $47.0M (Q3'25) vs $41.7M (Q3'24); gross profit $19.8M (42%);
  operating income $7.8M; net income $5.3M; basic EPS $0.09
- **R2:** Cash and equivalents $72.0M vs $78.4M prior year-end
- **R5:** Operating cash flow (headline row)
- **R20:** Proprietary Products $39.5M vs Distribution $7.5M

These are **plain HTML tables** with row labels in the first column and period columns
(3-month / 9-month / YTD, current vs prior year). Parsing is **label + column selection +
amount normalization** — not traversing XBRL fact graphs.

### Go types (mirror JSON)

```go
type FilingFinancials struct {
    Version     int              `json:"version"`
    Source      string           `json:"source"` // rendered_html | llm_fallback
    ExtractedAt time.Time        `json:"extractedAt"`
    Currency    string           `json:"currency,omitempty"`
    Period      FinancialPeriod  `json:"period"`
    Statements  StatementSets    `json:"statements"`
    ParseNotes  []string         `json:"parseNotes,omitempty"`
}

type FinancialPeriod struct {
    EndDate  string `json:"endDate,omitempty"`
    Label    string `json:"label,omitempty"`
    Duration string `json:"duration,omitempty"` // P3M | P9M | P1Y
}

type StatementSets struct {
    Income   []FinancialLine `json:"income,omitempty"`
    Balance  []FinancialLine `json:"balance,omitempty"`
    CashFlow []FinancialLine `json:"cashFlow,omitempty"`
    Segments []SegmentLine   `json:"segments,omitempty"`
}

type FinancialLine struct {
    Key         string   `json:"key"`
    Display     string   `json:"display"`
    Value       float64  `json:"value"`
    ValueFmt    string   `json:"valueFmt"`
    Unit        string   `json:"unit"`
    PriorValue  *float64 `json:"priorValue,omitempty"`
    YoYPct      *float64 `json:"yoyPct,omitempty"`
    File        string   `json:"file,omitempty"`
    Confidence  string   `json:"confidence"` // high | medium | low
}
```

**Version field** allows future schema bumps without breaking readers.

## Deterministic extraction algorithm

### P0 pipeline (per accession folder)

```
1. Skip if category ∉ {quarterly_results, annual_report} OR signals.hasFinancials == false
2. Glob R*.htm in accession dir (case-insensitive); index by basename R2.htm, R3.htm, …
3. For each target file (R3 → R2 → R5 → R20):
   a. Read HTML (UTF-8, ignore errors — same tolerance as build_meta)
   b. Strip scripts/styles; locate <table> rows
   c. For each canonical metric (see label dictionary), fuzzy-match row label in col 0
   d. Detect period columns from header row(s): prefer "Three months ended" current year
      over "Nine months" / "Year ended" for quarterly_results 6-K
   e. Parse numeric cell: ($47,023), 47.0, 47,023,000, em dash → nil
   f. Normalize to float + display format ($47.0M, $0.09)
   g. If prior-year column present on same row → priorValue + yoyPct
4. If ≥1 high-confidence income row → write financials.json; else skip file (no write)
5. Idempotent: skip if financials.json exists unless `--all` (same as meta batch)
```

### Label dictionary (canonical keys → aliases)

Maintain in `internal/edgar/financials/labels.go` — table-tested:

| `key` | Match aliases (case-insensitive, normalize whitespace) |
|-------|--------------------------------------------------------|
| `total_revenues` | total revenues, revenues, net sales, total net revenues |
| `gross_profit` | gross profit |
| `operating_income` | operating income, income from operations |
| `net_income` | net income, net earnings |
| `eps_basic` | basic earnings (loss) per share, basic eps |
| `eps_diluted` | diluted earnings (loss) per share |
| `cash_and_equivalents` | cash and cash equivalents, cash and short-term investments |
| `total_assets` | total assets |
| `operating_cash_flow` | net cash provided by operating activities |

Fuzzy match: normalize label → lowercase, collapse spaces, strip punctuation; accept if
alias is substring of row text or Levenshtein ≤ 2 for short labels.

### Column selection heuristics

| Filing kind | Prefer column header containing |
|-------------|----------------------------------|
| `quarterly_results` + 6-K | `three months ended` + latest year in header |
| `annual_report` + 20-F | `year ended` + latest fiscal year |
| Ambiguous (multiple 3M columns) | rightmost numeric column with a parseable amount |

Store chosen column text in `parseNotes` when ambiguous.

### Amount parsing

- Strip `$`, commas, `USD`, `US$`
- Parentheses `(123)` → negative
- Suffix `M` / `B` in cell or header → multiply (rare in R tables; handle if seen)
- `—`, `-`, empty → skip metric
- Format for display: `valueFmt` uses SI shorthand ≥ 1M → `$47.0M`, EPS → 2 decimals

### Confidence scoring

| Level | When |
|-------|------|
| **high** | Label exact alias match + numeric parse + expected column |
| **medium** | Fuzzy label + numeric parse |
| **low** | Conflicting columns or partial row — **do not write** unless LLM fallback enabled |

### Robustness requirements

- **Missing R files** — skip that statement set; still write partial `financials.json` if
  income parse succeeded.
- **Non-USD** — store `currency` from table header or `meta` if detectable; do not convert.
- **20-F vs 6-K** — same parser; column heuristic differs (annual vs quarter).
- **Re-run safe** — `financials.json` overwritten only with `--all` or when missing.
- **No network** — read only local `fileDB` files.
- **Byte stability** — sort keys in JSON output for diff-friendly regressions.

## LLM fallback (optional — P2, not P0)

Use only when deterministic extract returns **zero high-confidence income metrics** but
`signals.hasFinancials` and `R3.htm` exist.

| Option | When |
|--------|------|
| **Gemini flash-lite** | `LLM_PROVIDER=gemini`, structured JSON schema = `FilingFinancials` |
| **Local Ollama** | `LLM_PROVIDER=local`, same schema |

Rules:

- Pass **truncated R3/R2 HTML** (max ~32k chars), not whole accession folder.
- Prompt: extract ranked metrics only; return same JSON shape; `source: llm_fallback`.
- **Never overwrite** existing `source: rendered_html` with LLM output.
- Log accession + model + token count for audit.
- Feature-flagged env: `EDGAR_FINANCIALS_LLM=1`.

Deterministic path must ship and pass tests **before** LLM fallback is enabled.

## Risks

| Risk | Mitigation |
|------|------------|
| R*.htm layout varies by filer / form | Label dictionary + fuzzy match; table tests per form type |
| Wrong column picked (9M vs 3M) | Header regex priority; `parseNotes`; medium confidence → skip write |
| Foreign private issuers use different file names | Glob `R*.htm`; fallback to largest income-like table in primary doc (P1.1) |
| LLM hallucination | Deterministic default; LLM never overwrites high-confidence JSON |
