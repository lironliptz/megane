=== prompt ===
**Sell-side analyst coverage & research tracking** per company — discover who follows a
ticker, persist the roster, ingest their reports over time, extract structured fields,
and analyze the deviation between analyst expectations and actual reported results alongside
subsequent stock price reactions.

Builds on **prompt 1** (company page, `CompanyStore`, CIK identity), **prompt 3** (tabbed
company view + hash routing), **prompt 4** (stock prices), **prompt 6** (timeline events + modal pattern),
**prompt 8** (sidecar JSON artifacts + batch CLI ingest), and **prompt 10** (timeline event lanes).
**Greenfield** — no analyst code exists today; only this spec and its HLD.

This prompt does **not** replace SEC filing ingest (`fileDB` EDGAR tree). Analyst research is
a **parallel corpus**: broker PDFs/HTML, price targets, ratings, and narrative — orthogonal
to `meta.json` / `financials.json`.

## Problem (current behavior)

Megane today is **SEC filing intelligence**:

| Layer | Today |
|-------|--------|
| Company identity | `fileDB/companies/{cik}/submissions.json` |
| Filing corpus | `{year}/{accession}/meta.json`, optional `financials.json` |
| Timeline | Filing events + stock prices — no sell-side research overlay |
| DB | `stock_prices`, `stock_price_coverage` — no analyst tables |

Every public company has **sell-side analysts** (and sometimes independent shops) publishing
coverage, estimates, and rating changes. Users cannot today:

1. See **who covers** a company they are researching.
2. **Track new reports** from those analysts over time.
3. Compare **price targets / ratings / estimate revisions** alongside SEC events on the timeline.
4. Feed structured analyst data into **prediction or scoring** models to analyze the deviation between expectations and reported results.
5. Correlate earnings surprises (deviations) with subsequent stock price movements.

## Critical Realization & Data Audit (HLD Findings)

A thorough data audit of public free-tier APIs (Finnhub, FMP, Polygon) reveals a critical constraint:
**Individual analyst names (the actual persons) are NOT obtainable from free/public tiers.**

* Finnhub's `recommendation-trends` and `price-target` return aggregate counts and consensus figures only.
* Finnhub's `upgrade-downgrade` and FMP's `grades` return the **firm name** (e.g., "JP Morgan", "Benchmark", "Stifel") as the author, not the individual person.

### The Ladder of Reality:
* **Consensus metrics & Firm names:** Genuinely obtainable from free/public APIs (Tier 2).
* **Individual analyst names & PDF reports:** Only obtainable via manual curation (Tier 1) or licensed feeds like Refinitiv/Bloomberg (Tier 3).

### Architectural Pivot:
1. **Firm-First Schema:** The primary coverage entity is the **firm** (`(cik, firm)`), with the individual `analyst_name` being **nullable**. A row with no person is a normal, honest result of automated discovery.
2. **Consensus-First UI:** The `#analysts` tab leads with an aggregate consensus panel, followed by a firm-level coverage table. Individual names appear only where manually curated or imported.
3. **Withholding over Hallucinating:** The UI explicitly states: *"Firm-level coverage from {provider}. Individual analyst names require a licensed feed or manual entry."*

## Scope & non-goals

**In scope**
- **Sell-side equity research** tied to a **CIK + ticker**.
- Report types: initiating coverage, update, rating change, estimate revision, industry note.
- Metadata: firm, analyst name(s) (optional), report date, rating, price target, headline summary.
- File artifacts: PDF preferred; HTML acceptable (manual/import only).
- **Surprise & Price Reaction Analysis:** Calculation of deviations between consensus expectations and reported results (Revenue, EPS) and subsequent 1-day, 3-day, and 5-day stock returns.

**Out of scope**
- Insider / 13F holder tracking (separate `#ownership` tab).
- News sentiment scrapers without named firm attribution.
- Scraping broker portals that prohibit automation.
- SEC EX-99 research scanning (data audit shows no research PDFs in the corpus).

### SQLite Tables (Migration v34)

```sql
-- One row per (cik, firm, analyst_key)
CREATE TABLE IF NOT EXISTS company_analysts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  cik TEXT NOT NULL,
  firm TEXT NOT NULL,
  analyst_name TEXT,                  -- NULLABLE: firm-level coverage is normal
  analyst_key TEXT NOT NULL,          -- normalized slug: slug(firm) or slug(firm)|slug(name)
  status TEXT NOT NULL DEFAULT 'active',  -- active | dropped | unknown
  discovered_via TEXT NOT NULL,       -- manual | finnhub | import
  first_seen_at TEXT NOT NULL,
  last_seen_at TEXT NOT NULL,
  UNIQUE(cik, analyst_key)
);

CREATE TABLE IF NOT EXISTS analyst_reports (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  cik TEXT NOT NULL,
  report_id TEXT NOT NULL,            -- matches folder under analyst-reports/
  firm TEXT NOT NULL,
  report_date TEXT NOT NULL,          -- YYYY-MM-DD
  rating TEXT,
  price_target REAL,
  title TEXT NOT NULL DEFAULT '',
  source TEXT NOT NULL,               -- manual | finnhub | import
  document_sha256 TEXT,
  created_at TEXT NOT NULL,
  UNIQUE(cik, report_id)
);

-- Historical consensus estimates per reporting period (for deviation analysis)
CREATE TABLE IF NOT EXISTS analyst_period_consensus (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  cik TEXT NOT NULL,
  fiscal_year TEXT NOT NULL,          -- e.g., "2025"
  fiscal_period TEXT NOT NULL,        -- "Q1" | "Q2" | "Q3" | "FY"
  consensus_date TEXT NOT NULL,       -- YYYY-MM-DD (as-of date of consensus)
  revenue_estimate REAL,              -- consensus revenue estimate
  eps_estimate REAL,                  -- consensus EPS estimate
  rating_buy_count INTEGER NOT NULL DEFAULT 0,
  rating_hold_count INTEGER NOT NULL DEFAULT 0,
  rating_sell_count INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  UNIQUE(cik, fiscal_year, fiscal_period, consensus_date)
);

-- Coverage / fetch bookkeeping (mirrors stock_price_coverage)
CREATE TABLE IF NOT EXISTS analyst_coverage (
  cik TEXT PRIMARY KEY,
  status TEXT NOT NULL,               -- idle | fetching | ok | error | no_data
  provider TEXT NOT NULL DEFAULT '',
  last_attempt_at TEXT,
  last_success_at TEXT,
  next_retry_after TEXT,
  note TEXT NOT NULL DEFAULT ''
);
```

*Note: When a person is later supplied for a firm-only row, the row is upgraded in place (`UPDATE ... WHERE analyst_key = slug(firm)`) to prevent duplicate firm rows.*

## Deviation & Price Impact Analysis Engine (P2)

To understand how analyst expectations affect stock prices, the system must correlate consensus estimates with actual reported filings and stock price changes.

### 1. Surprise (Deviation) Calculation
For a given reporting period (e.g., FY 2025 or Q2 2025):
* **Actuals:** Extracted from `financials.json` (via prompt 8/9).
* **Expectations:** The latest `analyst_period_consensus` row recorded *just prior* to the filing date.
* **Surprise % Formula:**
  $$\text{Surprise \%} = \frac{\text{Actual} - \text{Estimate}}{\text{Estimate}} \times 100$$

### 2. Post-Announcement Price Impact
Calculate the stock price reaction over three horizons starting from the filing date ($T_{0}$):
* **1-Day Return ($T_{+1}$):**
  $$\text{Return}_{1\text{D}} = \frac{\text{Close}_{T+1} - \text{Close}_{T-1}}{\text{Close}_{T-1}} \times 100$$
* **3-Day Return ($T_{+3}$):**
  $$\text{Return}_{3\text{D}} = \frac{\text{Close}_{T+3} - \text{Close}_{T-1}}{\text{Close}_{T-1}} \times 100$$
* **5-Day Return ($T_{+5}$):**
  $$\text{Return}_{5\text{D}} = \frac{\text{Close}_{T+5} - \text{Close}_{T-1}}{\text{Close}_{T-1}} \times 100$$

*Note: If $T_{0}$ is a non-trading day, snap to the next trading day for $T_{0}$ and use the preceding trading day for $T_{-1}$.*

## Compliance & Security
- **Private-by-Default:** Research PDFs are proprietary. They are served only through authenticated session routes, never stored in a public static directory, and never exposed to public CDNs.
- **License Tracking:** `report.json` records the exact `source` and provider to audit redistribution rights.
- **Rate-Limiting:** Background fetchers honor `Retry-After` headers and enforce a minimum 24-hour fetch cool-down per CIK to prevent API key exhaustion.

## Downstream Prediction Integration (P3)

The ultimate goal of sell-side tracking is analyzing **expectation deviations** (revisions/consensus vs. SEC actuals) and their impact on share prices.

Provide a query helper in `internal/db/analysts.go` that joins `analyst_reports` (expectations) with `financials.json` (SEC actuals) and `stock_prices` to export a clean CSV for machine learning models or prediction tabs.

## Pitfalls to Avoid
- **Confusing "coverage":** SEC filing date span (`filedb.Coverage`) is completely separate from analyst coverage. Always name tables and APIs `analyst_coverage` or `company_analysts` explicitly.
- **Page-Load Fetching:** Never trigger external API calls during a page load. Read solely from the SQLite cache; let the background CLI handle refreshes.
- **Duplicate Firms:** Ensure the `analyst_key` update logic is bulletproof so adding an analyst name to an existing firm-only row updates the row in-place instead of creating a duplicate.
